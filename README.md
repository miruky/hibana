**Three.js と Rapier で構築した、インストール不要でブラウザからそのまま遊べる 3D FPS です。** 物理・戦闘・決定論的な衝突ステージは TypeScript、31 面の高密度環境と敵兵は Blender 製 glTF、効果音と BGM は Web Audio、UI は SVG / CSS を中心とするハイブリッド構成です。外部 3D アセットが欠損してもプロシージャル外装へ切り替わり、試合を止めない設計です（コードネーム: hibana）。

**▶ 遊ぶ: https://miruky.github.io/reflesh-fps-game-miruky/**

## 概要

手作りの 31 ステージを舞台に、10 種のゲームモードと 11 章 61 ミッションのストーリーで BOT と戦う一人称シューターです。リコイルパターン、射撃ブルーム、ADS、タクティカル / 空リロード、部位ダメージ、距離減衰、壁貫通、4 種の投擲物、42 挺の武器と 12 種の光学サイトを組み合わせるクラス作成（Create-a-Class）といった FPS の中核メカニクスを、ゲームエンジンに頼らず TypeScript で実装しています。キルカメラ、ステージ別の大気表現と BGM、動的 DPR、画質 tier / 距離に応じた LOD 配信を組み合わせ、WebGL の予算内で密度の高い FPS 体験を目指しています。

### なぜ作ったのか

リアルタイム 3D・物理シミュレーション・ゲーム AI・HUD 設計・オーディオ合成を 1 つの題材で横断するポートフォリオとして作成しました。FPS は「気持ちよく動いて当たり前」のジャンルであり、入力遅延、固定タイムステップ、レイキャスト判定、反動制御、照準とサイトの一致といった低レイヤーの品質がそのまま体験に出ます。エンジンを使わずに組むことで、その全てを自分の責任範囲に置いています。

### 開発状況

コア戦闘ループ（移動・射撃・BOT 戦）、戦闘拡張（投擲物・武器アタッチメント・42 挺の武器・スライディング / マントリング / リーン・壁貫通・部位ダメージ）、モード拡張（10 モード + 61 ミッションのストーリー・BOT 同士の交戦・拠点制圧・観戦カメラ）、メタゲーム（XP・アンロック・任務・レート・通算戦績）、素手格闘モード（空中降下衝撃波）、戦車ボス / ドローン / 固定砲台の敵種、キルカメラ、ステージ別のアトモスフィアと BGM、IGNITION FRAME UI、ゲームパッド対応、色覚サポートなどを実装済みです。環境配信パックは 31 面 × 3 段階 LOD と、各面に 2 基ずつ計 62 基の固有大型ランドマークを持ちます。人型 BOT 用には 6 兵科、共通 22 ボーン、14 クリップの Blender 製表示パックがあります。これらの外部表示は medium / high 画質で使い、low 画質や読込失敗時は TypeScript 製の表示へフェイルオープンします。対人マルチプレイヤーは未実装です。要求一覧と実装境界は [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) に記録しています。

## アーキテクチャ

![FPS-reFlesh のアーキテクチャ](docs/architecture.svg)

物理とゲームロジックは固定 60Hz で更新し、描画と視点操作はディスプレイのリフレッシュレートに追従させています。HUD は DOM で構築し、毎フレームのスナップショット（イミュータブルな状態の写し）だけを受け取るため、ゲームロジックから UI への参照は一方向です。描画は Three.js の EffectComposer 上でブルーム・Neutral トーンマップ・カラーグレード・被弾演出を合成し、負荷に応じて実解像度を自動で上下させる動的 DPR でフレーム時間を安定化します。

## 実装済みの機能

### 移動と射撃

移動系は WASD・スプリント・しゃがみ・ジャンプに加え、スライディング、壁へのよじ登り（マントリング）、ウォールラン / ウォールジャンプ、スラスト二段ジャンプ、Q / E でのリーン、コヨーテタイム、ジャンプ入力バッファ、落下ダメージ、移動状態に連動する足音まで実装しています。射撃系はヒットスキャン、武器ごとのリコイルパターン、連射で増えるブルーム、ADS による精度・速度・FOV の変化、タクティカル / 空リロードの使い分け、武器切替、近接攻撃を備え、ADS 時は各武器のアイアンサイト / 光学が画面中央（＝弾着点）へ一致します。一人称モデルは茶系の布袖とフルフィンガー軍用グローブを別材質で描き、武器ファミリ別の把持姿勢とタクティカル / 空リロード動作を持ちます。クナイ 4 形態、杖、弓、扇も専用グリップの対象です。指の交差・手掌の貫通・武器への不自然な重なりは、単体テストに加えて実ブラウザの無音 headless 連番キャプチャで監査します。武器を持たない素手格闘モードでは、空中でボタンを押すと降下して衝撃波で着地する専用アクションを行えます。

### 兵装（Create-a-Class）

メイン/サブ/特殊兵装は AR・SMG・DMR・スナイパー・ショットガン・バーストライフル・LMG・マークスマンなど合計 42 挺で、サイト・マズル・グリップ・マガジンの 4 スロットにアタッチメントを組み合わせられます。光学サイトはリフレックス・ホログラフィック・ACOG・可変倍率・サーマル・ハイブリッドなど 12 種を用意し、覗くとレンズ越しに背後が透けて見える正しい描画と、種類ごとに識別できるレティクルを持ちます。兵装画面は 3D の武器プレビューとステータスバー・派生スタット（DPS / 確殺弾数 / TTK）を備えた家庭用 FPS 系のクラス作成 UI です。

武器別の迷彩ラダーは Gold → 同クラス全武器 Gold で Diamond → 迷彩対象の全武器 Diamond で Dark Matter へ進みます。通常メイン武器の Gold は 500 キル + 100 ヘッドショット、特殊兵装と業火 RL はヘッドショット不要の 500 キル、サブ武器はヘッドショット不要の 250 キルです。サブ武器にも全迷彩と独立したクラス達成判定があります。Gold は装填・持ち替え、Diamond は ADS・集弾・反動制御、Dark Matter は全ハンドリングを Diamond 以上へ高め、最終報酬としてダメージを 1.5 倍にし全弾道を黒へ統一します。Diamond は反射を抑えた銀色スタッド、Dark Matter は黒帝を着想源とする黒曜石状の外装です。

### 敵とゲームモード

BOT は視野と遮蔽・煙幕を考慮した索敵、発砲音への警戒反応（サプレッサーで抑制可）、フラッシュによる失明を備えます。人型の交戦移動は前進・後退による間合い調整を主役にし、横移動は狙撃可能性を残す小さな補助ステアとアンスタック時だけに抑えています。人型外観は rifleman / breacher / scout / marksman / support / medic の 6 兵科を持つ共通リグの Blender 製兵士で、idle、ready、aim、fire、reload、前後左右移動、走行、被弾、死亡を含む 14 クリップをゲーム状態へ同期します。現行の外部兵士差し替えは medium / high 画質の非ゾンビ・非訓練モードが対象で、AI・衝突・ヒットボックスは従来の TypeScript / Rapier 側を使います。3 段階の腕前を選べ、敵種は人型に加えてドローン・戦車ボス・固定砲台があり、精鋭 / ボスの強化個体も登場します。投擲物はフラグ・スモーク・フラッシュ・焼夷の 4 種で、投擲前に弾道プレビューが表示されます。ゲームモードは FFA、TDM、ドミネーション、S&D、ハードポイント、キルコンファーム、ガンゲーム、ゾンビ、訓練、スコアアタックの 10 種と、11 章 61 ミッションで進むストーリーモードです。

### 演出・オーディオ・映像

BOT に倒された直後は、相手が発砲していた一人称姿勢・銃・射撃モーションを保つキルカメラへ切り替わり、どこから撃たれたのかを把握できます。31 ステージの配信パックは、テーマ別の密集市街、固有ファサード、屋上設備、道路・広場、実ジオメトリの中遠景と、各 2 基ずつ計 62 基の固有大型ランドマークを持ちます。これらのランドマークは可視シルエットとナラティブを担う外装であり、全ての内部が進入可能という意味ではありません。実際の戦闘動線・進入可否・衝突は `src/game/stage.ts` と `src/game/stages.ts` を正とします。遠景用の円筒画像壁は Blender GLB の読込完了後に隠します。ステージ全体は high で LOD0、medium で LOD1 の必要な 1 ファイルだけを通信・デコード・常駐させ、low は外部 GLB を要求しません。LOD2 は将来の sector / HLOD 配信と制作検証用に保持し、材質単位の統合メッシュと動的 DPRも併用します。GLB が欠損・不正・非対応の場合は、TypeScript 側の同じ衝突・スポーン・経路を保ったまま軽量外装へフェイルオープンします。時間帯やテーマに応じたプロシージャル雲・草・環境パーティクル・接地霧・水面・局所灯も重ねます。効果音と BGM は Web Audio で構成し、UI は家庭用 FPS の計器表現を参考にした IGNITION FRAME デザインシステムで統一しています。

### メタゲームとアクセシビリティ

試合結果はプレイヤープロフィールに積み上がります。勝敗・キル・ヘッドショット・拠点制圧などから XP を獲得してレベルが上がり、武器・アタッチメント・光学はレベル到達で順次解放されます。任務（チャレンジ）の達成で追加 XP を得て、完走した試合はレートを変動させて階級に反映します。通算戦績はメイン画面に常時表示され、記録は localStorage に保存するほか JSON ファイルとして書き出し・読み込みができます。アクセシビリティ設定として、敵味方の配色変更（色覚サポート）、画面揺れ軽減、HUD サイズ、ADS / しゃがみのホールド / トグル切替、Y 軸反転、UI アクセント色、試合時間、画質ティアなどを設定画面から調整できます。設定値は範囲外や壊れた値を読み込み時に既定へ補正します。

## プロジェクト構成

- `src/core` — 入力（ゲームパッド含む）、ゲームループ、シード付き乱数、音・BGM 合成、設定とプロフィールの永続化
- `src/game` — 弾道計算、武器、光学（optics）、アタッチメント、投擲物、モードルール、弾倉、反動、プレイヤー、BOT、ステージ生成、バイオーム、キャンペーン、進行度、メダル、チーム配色、試合進行
- `src/render` — エフェクト、多材質・骨付き両腕の一人称ビューモデル、全ステージ固有ランドマーク、アトモスフィア、カラーグレード、ポスト処理、兵装プレビュー、高密度 glTF / KTX2 / Draco / Meshopt / LOD アセット基盤
- `src/ui` / `src/ui2` — 共有HUD状態機、クラシックUI、既定の焔座UI2（必要な実装だけを遅延読み込み）
- `public/assets/aaa` — 配信用の 31 ステージ・敵兵 GLB、LOD とアセット manifest
- `tools/blender/a23` — 31 面共通のステージ生産ツールチェーン（再配分・区画・材質・計測・多カメラ証拠）。詳細は [docs/A23_TOOLCHAIN.md](docs/A23_TOOLCHAIN.md)
- `tools/blender` — 決定論的 Blender 生成、最適化、構造・予算・見た目の検証パイプライン
- `docs` — 要件定義書、アーキテクチャ図、全ランドマーク台帳、敵兵制作仕様
- `.github/workflows` — CI と GitHub Pages デプロイ

## はじめ方

### 前提条件

- Node.js 22.12.x（`.nvmrc` / `.node-version` / `package.json#engines` で固定）

### セットアップ

```bash
git clone https://github.com/miruky/reflesh-fps-game-miruky.git
cd reflesh-fps-game-miruky
npm install
npm run dev
```

### テストの実行

```bash
npm test
npm run test:e2e
```

Blender 配信アセットと実ブラウザ表示のリリース監査は別に実行します。ブラウザ監査は headless / muted で、キャプチャは Git 管理外です。

```bash
node tools/blender/validate-stage-profiles.mjs
python3 tools/blender/validate_dense_stage_assets.py
python3 tools/blender/validate_enemy_glb.py public/assets/aaa/enemies/soldier-pack-lod{0,1,2}.glb \
  --release --manifest public/assets/aaa/enemies/manifest.json
npm run audit:stages -- --quality=high
npm run audit:weapons -- --reload-kind=tactical
npm run audit:weapons -- --reload-kind=empty
```

### Lint の実行

```bash
npm run lint
```

### デプロイ

`main` ブランチへのプッシュで GitHub Actions がビルドし、GitHub Pages へ自動デプロイします。手元での本番ビルドは `npm run build` で `dist/` に出力されます。

## 設計方針

- **ハイブリッド・フェイルオープン** — 31 ステージと敵兵は Blender 製 glTF を manifest から非同期配信し、物理・衝突・ゲームロジックは TypeScript に保持する。3D アセットの欠損・非対応・読込失敗時はプロシージャル外装へ切り替え、試合を止めない
- **WebGL 向け高密度アセット配信** — 巨大ステージは画質 tier ごとに必要な 1 LOD だけを読み、人型モデル等は距離別 LOD を使う。Meshopt と任意の Draco / KTX2 に対応し、ローダー群は通常の Three.js 本体から分離した遅延チャンクで配信する
- **決定論的ステージ生成** — シード付き PRNG(mulberry32)でステージを生成し、同一性をテストで保証
- **固定タイムステップ** — 物理・ロジックは 60Hz 固定、視点操作と描画はリフレッシュレート追従で入力遅延を最小化
- **純粋ロジックの分離** — 弾道・反動・弾倉・ステージ生成・光学は DOM / GPU 非依存のモジュールとして切り出し、Vitest で検証
- **データ駆動の武器バランス** — 武器と光学の挙動は定義データの数値に集約し、調整がコード変更なしで完結
- **軽量維持** — 半解像ブルーム・動的 DPR・ティア別予算で、演出を盛りつつフレームコストを抑える
